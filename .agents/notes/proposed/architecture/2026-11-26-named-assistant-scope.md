# Agent Note: 命名助手固定配置与工具执行范围

Status: proposed

## Problem

临时 Pi workers 不提供可复用的具名职责和配置版本。用户需要选定研究员等助手，再在接回、分工或编辑角色后知道原任务实际用了哪个模型、指令和工具范围。只隐藏工具 schema 无法阻止嵌套调用，后台分工及按需加载还可能扩大工具列表。

## Proposal

在现有项目下保存必要角色配置及修订，新任务保存完整必要快照；执行、会话、模型接入与持久恢复继续由 Pi 1.4.0 负责。目录不启动任务，不改既有工作。角色初期由 owner CLI/API 管理，沿原 chat/run 选择。

使用 Pi 的原工具选择收窄可见/可用范围，并用固定 `ToolTask.beforeTool` 允许表检查每次实际调用。主任务、同步/后台子会话和嵌套调用共享同一快照；不会在每次调用重新读取最新目录。原后台 tools 显式配置要取交集。缺少 bash 时，也不能借 Goal 的命令核验执行任意命令。

与[原个人助手服务决定](../../implemented/architecture/2026-11-23-personal-assistant-services.md)部分重叠：原笔记负责 Pi 作为唯一会话/执行来源，本篇负责待实现的具名配置和权限范围。现有另一篇任务进度笔记与本提案无关，没有过时提案需要替换。[完整契约及源码](../../../../docs/specs/2026-11-26-named-assistants.md)

## Alternatives considered

只给角色加 instructions/model 最短，但工具范围将完全依赖模型遵守文字。仅设 modelTools 也不够；已安装 Pi 的真实实验显示嵌套执行仍能调用其他已启用工具。仅设 tools 又会被 control.addTools 扩大，因此保留原生选择与实际调用钩子两个层次。

把 discovery 的 LocalAgent 当角色目录能少一个文件，但它记录 Codex/Claude 等本机客户端，不包含职责、修订或实际执行范围。新角色只存必要业务配置，复用原子 JSON，不把本机发现结果升级为执行授权。

另建 Bot 运行时或复制参考项目的数据库/队列会重复 Pi 的能力。第一条产品路径保留原 TaskMeta 与 Pi ownership，完整团队和私有电脑后续单独接入。

## Acceptance criteria

目录及原任务 pin、模型/指令不随目录编辑变化，工具交集跨主会话、同步/后台子任务、嵌套、加载、恢复及压缩保持。有副作用的越界测试覆盖命令核验；允许的执行仍可交付。原默认任务与远程权限不变。产品入口完成后才把本篇转为 implemented。

当前只有五项原生 Pi 边界测试及合成实验通过，未接入角色目录，不能称命名助手功能已完成。

## Risks

工具选择、阶段配置和后台工具覆盖是容易遗漏的路径，必须结合实际调用和副作用检查。允许 bash 等工具仍给出现有本机执行能力；角色范围不是 OS 沙箱。旧任务使用固定版本，目录改动需要用户为新任务明确选择新修订，带来一次显式版本操作。

初期 owner 管理角色与后续模型管理工具分开，尚无自动建团队、助手私有记忆/电脑或完整协作能力；这些继续列为差距，不用角色目录代替。
