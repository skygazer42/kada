# Agent Note: 命名助手固定配置与工具执行范围

Status: implemented

## Problem

临时 Pi workers 不提供可复用的具名职责和配置版本。用户需要选定研究员等助手，再在接回、分工或编辑角色后知道原任务实际用了哪个模型、指令和工具范围。只隐藏工具 schema 无法阻止嵌套调用，后台分工及按需加载还可能扩大工具列表。

## Decision

Assistants 目录只保存项目角色配置及修订，新任务保存必要完整快照和解析后的模型。执行、会话、模型接入和持久恢复继续由 Pi 1.4.0 负责。目录保存不启动任务；owner CLI/API 管理配置，原 chat/run 选择明确 ID/修订。归档阻止新选择，既有任务从原入口管理。

Pi 工具选择与角色名单取交集，固定 ToolTask.beforeTool 允许表检查每次实际调用，afterTool 在提交 addTools 前过滤越界名称。后台分工保留角色扩展，并对显式 tools/modelTools 同时取交集；主任务、同步/后台子任务和嵌套调用共享同一原快照。重启、压缩和目录编辑不替换该快照。

当前 acceptance/CheckSchema 只有机械文件检查，不增加虚构的 command 分支。真实命令入口 criterion.verification 和 task_verify 要求 bash，后者通过原 Pi 嵌套 bash 执行并再次受允许表约束。角色工具是现有能力的上限，未授权连接或不存在的阶段工具不会因此启用。

新客户端要求 named-assistants capability，避免同版本旧服务忽略 assistant 参数后当普通任务执行。原消息接口拒绝换角色。指令字符串保留原空白/Unicode 码点，标签拒绝终端控制字符，部分编辑的 undefined 不清除已有模型。

与[原个人助手服务决定](2026-11-23-personal-assistant-services.md)部分重叠：原记录负责 Pi 作为唯一会话/执行来源，本篇负责命名角色、版本和范围。既有任务进度记录与此无关，没有过时提案需要替换。[完整契约及固定源码](../../../../docs/specs/2026-11-26-named-assistants.md)

## Alternatives considered

只给角色加 instructions/model 最短，但工具范围会依赖模型遵守文字。仅设 modelTools 也不够，真实 Pi 实验显示嵌套执行仍能使用其他已启用工具；仅设 tools 又会被 addTools 扩大。因此保留原生选择、结果过滤和实际调用检查三个位置。

把 discovery 的 LocalAgent 当角色目录能少一个文件，但它记录 Codex/Claude 等本机客户端，不包含职责、修订或实际执行范围。目录只存业务配置，复用原子 JSON/单 daemon 队列，不把本机发现结果升级为授权。

另建 Bot 运行时或复制参考数据库/队列会重复 Pi。第一条路径保留 TaskMeta 与 ownership，完整团队、私有记忆和独立电脑仍单列后续。修改现有任务以追随最新角色能少存一份快照，却会在恢复时扩大原授权，所以新版本只用于新选择。

## Consequences

25 项聚焦、全量 524 项通过，另 4 项可选 Office 跳过，类型/构建通过。两个实际 SIGKILL 场景覆盖元数据已保存和原读取待执行，目录后来获得写权限仍不扩大原任务。同步/后台子任务、后台待答后重启、原生压缩与 21 项 MCP 中的单项选择均有验证；额外脚本动作/加载也受同一名单限制。

DeepSeek V3.2 首轮确认 30 秒预算后在可选计划阶段到限，无产物；失败保留。第二轮明确 180 秒/100,000 token 后，用 6 次请求验证旧 v1 接回、新 v2 确认后写入一次与精确字节，bash 始终不提供。两轮共 12 次请求、41,924 已知 token，金额和中断请求账单未知，未作原生 Pi 净收益对照。

角色模型用于主会话；原任务若有指定 worker 模型，子任务继续该配置，否则 Pi 复制父模型。工具名单限制不构成 OS 沙箱，获准的 bash 等工具仍具有原有本机能力。版本操作增加一次明确选择，换取恢复时的可追溯范围。

模型创建/编辑角色、可视工具选择、团队、助手专属记忆/电脑及原生设备入口仍未完成。独立审查需使用不可变 Git 提交快照：Windows 本地读取改变 atime，会被审查器误判修改；不改安全检查，结论另记。
