# Agent Note: 助手群组复用原 Pi 会话、回执和设备权限

Status: implemented

## Problem

持久分工围绕一个原任务展开。它无法让用户在有成员身份的公开对话里轮流点名，也无法从配对手机接回群组记录。角色、公开内容和实际执行需要长期保持对应。

## Decision

群组沿用原任务目录和 Pi 持久存储。根会话保存公开消息，成员会话按群组内助手 ID 和修订建立。受理用户消息时在同一 Pi 事务写入消息、投递和稳定请求回执。最终答复引用成员的原 Pi 条目。成员可在同一截止时间和累计模型预算内逐位交棒，每位成员只能参与一次。阶段编号区分各自的原提交，旧单次交棒的输入 ID 保留。

本机按群组修订编辑标题和成员。修改会移除活跃答复者或潜在接棒者时，等原 Pi 回合停止再保存新成员配置。旧消息和回执保留。会话工具仅按群组内固定角色开放 `room_handoff`，接棒成员完成本轮文本答复。

本机输入可固定用户明确选择的文本附件。成员按原工具权限发布文本产出或读取该轮的附件编号。成员产出绑定原工具调用，独立于后续的回复和交棒回执。后续交棒沿原副本，被替换的固定副本按哈希拒绝。 [附件契约与验证](../../../../docs/superpowers/plans/2026-11-26-room-attachments.md)

手机沿用配对会话的查看与回复授权，附件下载单独授权。撤回查看同时撤回发送和下载。两台设备的请求 ID 通过配对身份隔离，附件请求在同一权限事务中读取和校验固定字节。浏览器在同一次配对会话保留草稿和稳定重试 ID。 [群组契约和源码](../../../../docs/superpowers/plans/2026-11-26-assistant-rooms.md)

## Alternatives considered

将所有助手放在根 Pi 会话并切换配置可少存几份会话，但会混合角色的私有提示和运行来源。独立原生成员会话保留每个助手的配置、用户请求和真实答复归属。

明确点名和逐位交棒由原 Pi 持久任务表达。多条用户消息的接收和投递见后续决定。 [群组消息排队](2026-11-26-assistant-room-queue.md)

## Consequences

状态核对覆盖受理、成员编辑、群内交棒、原答复、设备撤回以及两处强杀恢复。涉及群组的外部动作仅为选定模型的文本调用。群组复用原[命名助手的固定版本](2026-11-26-named-assistant-scope.md)和[持久同事的原生会话归属](../../proposed/architecture/2026-11-26-persistent-assistant-peers.md)。独立审核代理两次无法收到审查任务正文，本批验收依据作者审查、回归、硅基流动及本地 Chromium。
