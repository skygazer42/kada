# Agent Note: 个人助手能力沿用 Pi 的会话与任务身份

Status: implemented

## Problem

个人助手功能 Spec 的记忆管理、提醒、手机入口和分工需要持久身份。另建执行系统会重复 Pi 已有的恢复、等待、认证和用量机制，也会让历史任务难以接回。

## Decision

任务继续拥有独立 Pi Harness；模型引用、Skills 版本和已启用 MCP 工具清单固定到新任务。普通聊天只记录会话级记忆引用，创建 Goal 仍由现有任务准备流程决定。记忆列表的修订来自原事实；合并显示的重复事实保留各个原始版本引用。

提醒规则与发生项保存在 Pi session 文档，等待使用持久 task 的 sleepUntil。执行前以稳定发生项身份关联原有任务；通知只新增已读标记和单次提醒回执。例行任务可按已验收输出的持久哈希抑制相同结果的完成通知，失败及待答仍可见。

首个远程渠道是响应式 Web 页面。每个设备使用独立令牌，持久状态只保存哈希；手机不接收 daemon 管理令牌。宿主仍仅监听回环地址，跨设备访问使用用户已有的 HTTPS 反向代理及明确配置的 origin。受理回执先落盘再转入原任务 API；中断后按原身份查询，效果未知的请求不自动重发。远程执行和其 Pi 子会话只获工作区文件工具，所有阶段的 hook 检查真实 cwd、原始路径与 Pi 规范化后的路径。确认前只读，命令核验和宿主 Shell、MCP、电脑、全局记忆及 Skills 均不继承；完整命令执行留待现成隔离宿主。这是工具边界，不宣称 OS 沙箱。

记忆的待发送选择与实际使用分开保存。Pi generation.beforeRequest 重放实际 system sections，按选择身份记录提供的版本；检索结果先存待用引用，只有进入下一次模型请求才成为使用记录。配置、轮询、纠正及重启本身不会伪造新的使用历史。用户指定的语言优先，其次为相关已保存语言偏好，避免普通聊天的“跟随提问语言”覆盖保存的偏好。

用户目录已发现的方法进入同一目录，任务固定完整树版本。显式选择在任务受理前固定；默认选择在确认前准备。单个历史坏配置隔离为待处理，修复后可恢复，不阻断其他任务。手机对话读取持久 Pi 条目身份，下载 URL 绑定候选、修订与验收摘要，不使用可漂移的数组位置代表内容版本。

产物入口在打开或下载前重新检查工作区范围和已验收文件版本。macOS 客户端通过相同打开接口访问产物。日常电脑配置维持默认关闭，不启用 CuaDriver。用户已明确选择现有 agent-browser 做本地网页验收；通过原 ComputerBridge 和接管 API 执行，保留独立操作端与原任务身份。

已安装 0.38.1 的原生 MCP 可发现工具，但本地网页和空白页调用都超时。CLI 正常，因此使用现有 MCP SDK 薄适配固定页面、会话及截图输出；UI 动作仍由安装的 CLI 执行，不另造驱动、执行循环或调度器。适配不给任意 Shell/JavaScript，进程使用结构化参数和 shell:false。该 CLI 会把以 `-` 开头的填写值当作选项，连 `--` 也不能阻止，故明确拒绝，避免假成功。测试清理有独立截止信号；工作截止后仍实际关闭本次浏览器。

预算到限时，监督循环和重启入口允许已结清的当前候选完成本地验收。检查失败时保留报告，独立模型评审和返工等待额度。任务未固定 Skill 时，使用 Pi 的模型工具过滤，省去脚本工具定义。

接回时从 Pi 的原委派记录查询已有子任务结果，查询范围由父会话归属决定。常规任务状态保留完整用户要求，验收条目只显示预览，精确标准按需取得。手机会话概览复用任务分组，先确认设备归属再读取状态。待发送内容暂存在当前标签页，明确重试沿用原消息 ID，并在发送前重新检查回执。电脑动作已发出但回执失效时显示结果不明，回交后用重新观察核对原效果。

执行回合缺少正式提交时，监督提示沿用原 outbox，要求登记已经问过的问题或提交现有结果。发生验收错误时，沿用原返工提示。周期任务选择防重叠后，规则文档保留本修订最新的已受理任务。调度先释放规则事务再查任务状态，查询等待跟随 Pi 定时任务的取消信号，使预算结算可停止正在查询的定时任务。跳过事实追加到原 Pi 发生项记录，历史详情按需读取当前任务。

手机增量读取使用授权会话的 Pi 条目 ID，游标也会越过页面无需展示的条目。Chromium 页面切换会话时重置游标。固定浏览器适配器仅标记可互相替代的成功观察。Pi 请求钩子按租约和观察类型省略被替代的内容，持久记录保留完整结果。 [源码参考与验证](../../../../docs/experiments/2026-11-24-assistant-optimization-directions.md#本轮实现与验证)

周期规则暂停保留规则修订和已受理任务，恢复时用 Pi 创建新的未来定时任务。Pi 调用身份约束旧定时器的写入。间隔规则计算实际时间锚点，工作窗口使用明确的时区。手机操作版本绑定原 Pi 提交和任务状态，并在原状态队列内校验。手机接回仅使用原预算和时限。本机项目默认模型与记忆共用项目根，新任务保存选定模型供原会话继续使用。 [能力对照](../../../../docs/specs/2026-11-24-assistant-capability-parity.md)

手动运行在同一个 Pi 提交里保存请求回执与立即执行的持久任务，复用定时任务的预检及发生项历史。原规则的下次执行仍由日程计算。两个触发读取同一预检样本时，在事务中区分已受理基线与待受理样本。取消已暂停的任务时先撤回排队请求，再标记所有 Pi 活动任务，最后启动取消处理。

例行任务恢复时用 Pi 查询原生定时任务，并在恢复调度前关闭规则已撤销的实例。项目 MCP 设置只选择全局已启用工具的子集，创建任务时固定工具和连接修订。手机草稿按配对实例保存在浏览器，跨标签用 Web Locks 保存草稿和受理身份。异步委派让本地 Pi 后台任务拥有本批子会话，父任务用固定请求 ID 接回结果；候选交付检查原结果是否已进入父会话。

五字段 Cron 由 Croner 11.0.1 计算前后发生时刻，Pi 继续负责实际唤醒。项目记忆采集设置与来源刷新、模型写入共用原存储锁。关闭采集时保留原事实供召回，采集端按项目身份过滤。手机原消息的附件通过 Pi 提交条目和宿主回执关联，预览及下载读取经校验的原件。

本地事件使用规则显式匹配和事件摘要去重，立即执行复用原 Pi 定时任务的阶段。记忆审阅与事实保存在同一原子记录中，接受时核对来源和替代目标的版本。图片输入保存宿主原件引用，Pi 负责图片解码和缩放。已受理的待发消息恢复时先查原 Pi 提交，省去再次读取原件。

工作项查看与答复分别授权。本机 `work-items share-replies` 只给当前配对、已分享的工作项授予答复权限；`unshare-replies` 保留查看，`unshare` 同时撤回答复。原运行详情的 `answerVersion` 只在具备权限且主任务等待问题时提供。答复入口在配对队列内核对权限和任务归属，再由原运行的状态队列与 Pi 事务核对问题版本，保存答复摘要、用户消息和 outbox。摘要绑定请求 ID、显示版本与原文，重试只能复用同一答复。首次建立 Pi 文档中的嵌套回执表后，必须重新经代理写入表项，不能修改赋值表达式返回的临时对象。 [Suparagent 原任务答复](https://github.com/Anil-matcha/suparagent/blob/f2ae9d0f5cc4/backend/app/team/jobs.py#L829)

答复权限同时覆盖共享原运行当前批次的子任务问题。入口按配对实例和请求 ID 生成固定摘要，原子会话的 Pi 问题回执负责防重；暂停后沿原会话继续，子任务问题及浏览器尚未提交的输入保持原身份。运行控制用 `share-controls` 单独授权；撤回查看同时清除答复和控制权限。状态版本包含目标轮次，继续只移除手机暂停标记并唤醒原 Harness，保留预算、时限和子会话；本机暂停仍须由本机处理。 [Suparagent 运行操作](https://github.com/Anil-matcha/suparagent/blob/f2ae9d0f5cc4/backend/app/services/work_execution.py#L115) · [Codync 定向操作](https://github.com/leepokai/Codync/blob/9dae3e2bec9b/host/src/api/bots.rs#L358)

## Alternatives considered

另建聊天待办文件能少改原服务，但会使工作项、共享和原运行身份分叉，所以扩展既有 WorkItems。只在 Pi 工具回执记录成功能节省一份操作记录，但无法跨过文件已提交、工具尚未回执的崩溃窗口；摘要与历史结果同次保存在工作项。只保留最新回执会遗失旧工具恢复所需身份，所以当前不按数量裁剪；文件体积与后续清理政策须测量后再决定。

直接调用 owner list 再过滤可减少代码，但会先打开其他项目状态；项目目录先筛元数据。只用元数据推测状态可避免打开旧 Harness，却不能呈现 Pi 子任务待答、预算与交付，所以复用既有只读状态入口。该入口可能打开原存储做 Pi 投影，但不会启动 scheduler 或提交原工作；不同于仅取旧讨论的 history 工具，目录需要当前业务状态。

自建搜索、加载、执行代理可定制排序及中文分词，但 Pi 已提供工具检索和原生加载状态；增加代理会再做参数与权限入口。一次发送所有 schema 接法最短，但大型清单把无关工具结构带到每次请求；按已有参考的 20 个工具阈值为新任务选择延迟注册，旧任务保留原快照行为。只隐藏 modelTools 中的 delegation_ask 不足以限制搜索，因为 Pi 从 enabled deferred 清单检索，所以在主会话的 tools 范围排除它。

另建 FTS 或向量索引能改善大规模检索和排序，但当前 Pi 已保存完整可分页历史；先从原存储做有限结果的字面查询，避免索引同步和恢复。复用整个旧任务 open 更短，却会装载工具、配置并让检索影响运行时；只取 Pi Storage，必要的已有格式迁移仍交给 Pi。直接把所有上下文条目当历史更全面，却会混入监督和工具结果，所以以原用户提交与回答身份作范围。

只要求用户使用 `/remind` 无须增加模型工具，却不能完成普通中文对话里的提醒要求。把所有例行任务接口暴露给聊天能覆盖更多功能，但同时带来未来执行和预算权限；当前只给通知型日程薄工具，新 managed 聊天才扩展周期和修改。另建提醒存储更方便做专用页面，却会重复原 Pi 定时与通知恢复，因此复用既有规则和 inbox。只在工具进程内记修改成功可少一次持久写入，却无法处理规则已提交但工具尚未回执的中断，原规则事务和原工具输入快照各自承担必要的恢复边界。

额外模型探测能立即发现账户修复，但会添加付费请求和第二套失败状态。当前从原任务读取已经发生的结果，手动执行及原日程提供明确的检查机会。解析所有供应商自然语言重置时间能缩短等待，却没有统一的 Pi 持久机器字段契约；只用可核对的拒绝标识和固定上限，未知错误不猜测。默认开启会改变已有用户的自动规则，因此显式 opt-in。

通用透传全部 GitHub 事件更快扩大事件数量，但会把用户编写的文本和不明确的字段契约交给原任务。PR 延续现有 Issue 的小型投影，明确保存完成该任务所需的提交身份。复用 Issue 元数据字段会更短，却无法区分 PR 的 head/base SHA；增加一个可选字段保留旧 Issue 和历史任务行为。外部内容仍由现有工具按已保存目标获取。

每次检查都启动模型可以更灵活地判断是否需要跟进，但近期用户活动和固定运行间隔可以从原持久记录判断。另存一套活动数据库更便于聚合，却增加恢复与身份同步；这里复用 Pi 目标状态、提交和已有本机元数据。当前活动只代表 Kada 使用记录，不推断用户在场或授权新的工作。

另建应用账号库可以提供统一连接页面，但会重复现成 MCP 服务的授权、令牌和工具权限管理。当前预检直接使用已有服务，账户授权仍由连接器自身完成。每次启动模型来判断是否变化更通用，但相同工具内容的指纹足以避免本次额外模型请求；复杂的内容筛选仍可使用已支持的命令预检。

OAuth 自行实现授权码、PKCE 和刷新可细控界面，但已安装 SDK 支持这些协议及 issuer 绑定，因此只实现存储与本机入口。直接复用环境变量令牌更短，但需要手动管理续期，不能覆盖用户浏览器登录；原方式保留为另一种显式配置。

单次 MCP 审批复用 Pi 目标待答与持久任务。审批阶段保存准确参数和任务修订，获得允许后由持久任务在派发前记录意图，同一请求 ID 将结果回送父会话。再发一个普通工具指令会让模型重新生成参数，无法证明派发的参数就是用户看到的版本。项目工作项独立保存项目身份和目标修订，任务自身作为运行回执。

共享工作项的答复若转发到手机当前聊天，接法更短，却会改变接收任务。答复直接进入原 Pi 运行；只读分享不隐含本机执行权限，因此答复另行授权。页面保留当前展开运行的输入与待发请求，重试复用原请求 ID，不复制本机工作区到远程聊天。

macOS 任务卡通过本机任务视图展示脱敏参数，决定提交原动作 ID 和摘要。手机待处理列表沿用设备会话查询和原会话选择流程。

手机审批授权随当前配对记录保存，绑定本机任务、动作 ID 和参数摘要。手机读取脱敏预览，提交时在设备队列中再次校验授权，再交给原任务受理。授权的撤回与决定受理串行，重新配对生成独立的授权范围。审批执行及其回执继续由 Pi 保存。 [Suparagent 待处理审批](https://github.com/Anil-matcha/suparagent/blob/f2ae9d0f5cc4/backend/app/team/needs_you.py#L155)

手机工作项授权绑定当前配对和工作项 ID，覆盖后续修订和关联运行。详情从原任务读取状态、待答和交付摘要，待处理项优先。同一配对的授权读取和撤回串行。 [Suparagent 工作项待处理状态](https://github.com/Anil-matcha/suparagent/blob/f2ae9d0f5cc4/backend/app/team/needs_you.py#L232) · [运行状态读取](https://github.com/Anil-matcha/suparagent/blob/f2ae9d0f5cc4/backend/app/services/work_execution.py#L49)

展开历史运行先用原任务元数据核对工作项归属，再打开 Pi 状态。手机详情只投影该次运行的目标、步骤、待答和摘要。撤回分享后的请求在授权检查处结束，页面也丢弃此前未返回的详情。

后台子任务把问题和用户答复保存在 Pi 子会话文档。父任务的监督循环检查修订和预算后，用固定请求 ID 提交到原子会话。等待期间批次以 Pi 持久休眠释放执行阶段。重启时使用原批次、问题和已受理的回复，其他子任务仍可独立完成。

`delegate_send` 在同一子会话文档保存追加指令，用主助手的工具任务 ID 生成固定请求 ID。父任务监督循环在检查预算后通过 Pi 的 `steer` 派发，批次按提交状态等待结果。用户待答优先于未派发的指令。若已有指令进入 Pi 队列，子助手会先收到该指令，再决定是否需要提问。 [Pots 追加指令](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/agent/children.ts#L578)

macOS 任务卡从原任务视图读取子任务问题，每张卡以父任务、子会话和问题的身份绑定输入。重试沿用该卡的请求 ID。普通任务草稿由原有输入框保管，子任务答复通过定向端点提交。

手机 Web 沿用原会话的设备配对和工作区校验，答复再核对原子会话、批次修订和问题 ID。远程后台子会话沿用该工作区的文件工具和路径检查，问题和回执仍由 Pi 持久化。待处理列表只投影问题文字，详情页提供定向答复所需的身份。 [Suparagent 待处理问题](https://github.com/Anil-matcha/suparagent/blob/f2ae9d0f5cc4/backend/app/team/needs_you.py#L201)

单个子任务的停止标记也保存在原 Pi 子会话文档。首次提交和写入停止标记在同一任务内串行，队列在等待执行结果前释放。恢复时先撤回已停止子会话的排队输入，并标记其在途任务，再启用 Pi 调度。 [Pots 停止与恢复](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/agent/agent.ts#L884)

手机停止单个子任务时，入口核对设备归属和原会话工作区，再由 Pi 校验父任务修订和后台批次。重试沿用原子会话的停止标记。 [Suparagent 单任务停止](https://github.com/Anil-matcha/suparagent/blob/f2ae9d0f5cc4/backend/app/team/jobs.py#L279)

中断工具时从 Pi 的实时文档取得目标子会话的在途工具 ID，并中止这些 Pi 任务。原生成任务读取工具中止回执后可以继续执行。等待确认有时限，超过时限的调用显示为待确认。 [Pots 工具中断](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/agent/agent.ts#L823)

桌面任务卡与手机共用可操作子任务和工具的投影。桌面请求通过本机管理 API 传递具体调用 ID，终端仍可按子会话中断它当前运行的工具。桌面中断的请求时限覆盖服务端等待退出的 15 秒。

纯事件规则只在接受事件或手动运行时创建 Pi 执行任务。公开 GitHub Issue 支持本机 CLI 手动同步，也可由 daemon 按用户配置的规则 ID 持续轮询。两种入口针对同一规则和仓库共用文件锁及游标。规则按原修订受理后推进游标，原事件重投可取回已有回执。轮询遵循 GitHub 的限流和重试间隔，daemon 关闭时取消在途网络请求。 [DuskBot 游标实现](https://github.com/DuskBotAI/duskbot/blob/18df35a445e3/server/app-triggers.ts#L451)

GitHub Issue Webhook 在 owner 配置的规则路径启用，secret 只引用环境变量，对最多 1 MiB 原始字节做 HMAC-SHA256 验证；不接受 daemon 令牌代替验签。UTF-8 JSON 验证后仅投影仓库和正整数编号，规则修订交给原 receiveEvent 再核对。事件身份来自签名正文哈希，不能使用未签名 delivery header，否则复制签名、改 header 就能重复受理。回执和待执行 Pi 任务由原事件事务一起保存，响应未知返回可重试的 503，重投不建立第二套队列。 [Rakazo 原始验签与正文防重](https://github.com/elie222/rakazo/blob/e64d73292179/apps/api/src/webhooks/github-webhook.ts#L163)

GitHub 规则接受事件时从安全标量投影仓库与编号，随原发生项保存，再通过 task metadata 的 routineIssue 恢复到模型提示。否则 Webhook 会启动助手却无法告诉它具体 Issue。原规则目标、工具与预算不变；仓库正文仍须用现有工具读取并当作不可信数据。任务创建摘要包含该投影，原 ID 不得换绑其他 Issue。其他事件数据仍只用于匹配，避免把外部任意字段提升为指令。

手机 Web Push 以 Pi 的原会话事件为来源，每个配对保存订阅和已受理的事件位置。锁屏内容只显示通用提醒，通知点击经配对与会话归属检查后打开原会话。浏览器推送中继仅接受已知 HTTPS 服务，服务端密钥留在本机数据目录。 [Codync 通知处理](https://github.com/leepokai/Codync/blob/9dae3e2bec9b/apps/android/app/src/main/kotlin/com/codync/android/PushService.kt#L179)

远程子任务登记问题时，在同一个 Pi 事务中向父会话追加通用待答事件。重放同一工具调用沿用原问题和事件。问题正文只在已完成会话归属校验的详情接口中提供。 [Suparagent 待答通知](https://github.com/Anil-matcha/suparagent/blob/f2ae9d0f5cc4/backend/app/team/jobs.py#L483)

预算到限时直接停止监督的规则更简单，但会遗漏 Pi 已经结清、只等本地验收的候选。再发一次模型请求也可以让模型重提候选，但会消耗额度，且已有的持久提交足以做本地验收。

使用常见任务队列和独立数据库能提供通用的定时管理，但会增加第二套任务与恢复状态。当前 Pi 1.4.0 已提供持久等待和 ownership，直接使用这些公开能力。

手机直接复用 daemon 令牌能减少认证代码，但会同时获得模型设置、任意项目和其他设备的访问范围。独立设备凭据与会话归属检查保留派活和取回结果所需的能力。

由模型描述“没有变化”可以避免保存输出指纹，但无法独立解释是否应提醒。完成事件保存验收结果哈希，通知投影据此判断；不增加反思模型调用。

每次轮询返回完整历史使客户端恢复逻辑简单，长会话会因此重复传输同一批消息。原生条目游标让实时状态与新增历史共用原详情 API。直接改写浏览器工具的持久结果能减少存储，但会丢失事后核对所用的原观察，因此只在 Pi 发送请求时裁剪。

通过修改完整定义实现暂停能复用更新入口，但恢复会重置预检基线。周期暂停只移除原生定时任务，恢复时保留原定义。手机直接复用本机恢复入口会获得一轮新预算。手机接回只继续原提交。

## Consequences

聊天待办有 4 个实际 SIGKILL 场景验证操作重入和后续编辑保护；普通聊天、旧范围、分页/截断和聊天转 Goal 后撤下工具都有 Pi 回归。DeepSeek 经硅基流动完成保存、重启后改名/完成及归档，8 次请求、53,405 总 token，无 Goal/运行，金额未知。Chromium 390 × 844 验证已完成/归档待办与仍待答的原运行同时展示，展开原运行不改变未发送草稿；实体手机尚未验收。新增回执会增加原 JSON 大小，未证明大规模编辑性能或成本改善。

项目任务目录复用既有完整状态读取，减少状态分叉并保留原子任务的待答投影；它仍需遍历同项目任务，大量历史的延迟和跨页变动尚未量化。6 项 Pi 回归覆盖范围、截断、分页、坏存储、重启与聊天转 Goal；硅基流动 DeepSeek 的中文查询使用 4 次请求、20,844 总 token，金额未知，不能推出成本或任务质量收益。参考项目完整产品能力仍按能力核对表逐项补齐。

周期提醒的确定性回归验证每周通知、改为每日、保留原政策及无效输入拒绝。实际 SIGKILL 覆盖更新未提交、已提交后被再次编辑和已提交后被取消，回放保持原结果且不覆盖当前规则。DeepSeek V3.2 用 9 次请求完成中文创建、重启后修改和取消，原提醒 ID 保留，无 Goal；52,054 总 token 包含缓存，金额未知。当前不提供通知型 Cron/间隔、执行型任务或跨设备聊天管理，不据此声称全场景时间理解和成本改善。
