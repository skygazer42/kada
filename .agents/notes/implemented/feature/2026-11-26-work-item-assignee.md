# Agent Note: 工作项固定助手修订与配对编辑

Status: implemented

## Problem

工作项规划需要保存分配意图，用户启动时还要确认使用哪位助手。设备编辑需要沿同一工作项修订及原回执处理，防止冲突覆盖和重复保存。

## Decision

工作项只保存同项目助手的 ID、修订和当时名称。新运行通过原 Runtime.create 选择当前可用的指定助手并保存 Pi 配置，原运行和原请求重放继续使用初始角色。工作项变更沿原项目、修订、请求摘要和原子回执，日历与看板使用同一工作项。 [具体实现与参考源码](../../../../docs/superpowers/plans/2026-11-26-work-item-assignees.md)

配对设备的工作项编辑权独立授予，随查看权撤回。编辑只提交原工作项的计划字段，设备及请求身份进入防重摘要。旧修订冲突时手机保留草稿，并从原工作项读取可加载的字段。

## Alternatives considered

仅保存助手 ID 可以追随角色修改，但会让某张已分配卡片悄悄使用别的指令或工具。保存可读修订并在新运行校验它，可以区分重新分配与原运行重试。

手机可直接兼用本机工作项接口，但会扩大配对设备可访问的项目和字段范围。沿用共享工作项的逐项授权可复用同一原子保存并限制编辑字段。

## Consequences

本机聊天和看板可改变分配，手机可修改计划字段。自动化覆盖外项目助手、回执重放和旧修订冲突，硅基流动验证原角色的准备与确认，Chromium 验证原卡片变更、冲突草稿和撤回。 [角色实测](../../../../docs/experiments/2026-11-26-work-item-assignee-siliconflow.json) · [浏览器记录](../../../../docs/experiments/2026-11-26-work-item-mobile-edit-browser.json)
