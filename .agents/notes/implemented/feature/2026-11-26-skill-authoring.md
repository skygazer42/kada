# Agent Note: 原生 Skill 导入与版本导出

Status: implemented

## Problem

已验收的任务可以捕获 Skill。用户自写或从同事得到的原生包也需要保存、修订及再分享，同时留住已经开始的任务所用的字节。

## Decision

本机管理沿用 SkillStore 的版本内容、头记录和回退机制。显式导入校验当前版本并记录原工作区来源，后续任务仍由原生 Pi 固定选中版本。导出沿当前目录的实际版本复制并核对完整目录哈希，保留 UTF-8 BOM 与空目录。 [参考实现和验收](../../../../docs/superpowers/plans/2026-11-26-skill-authoring.md)

助手配置保存完整版本引用，缺省继承项目目录，空数组明确不选，清空后恢复继承。分配不扩大原工具权限。主会话、跨项目协作者和本机群组沿任务保存自己的原始副本；配对群组继续使用独立的共享聊天会话。跨项目原生读取只对已获授且通过完整包哈希检查的文件增加例外。 [分配范围与验收](../../../../docs/superpowers/plans/2026-11-27-assistant-skills.md)

与[会话身份记录](../architecture/2026-11-23-personal-assistant-services.md)部分重叠：该记录约束 Pi 的任务与权限归属，本篇维护 Skill 版本及分配语义。原决定继续成立。

## Alternatives considered

直接把编辑后的文件指向活动 Skill 可以保持一份副本，但旧任务会读到新内容，命令重放也无法说明使用了哪一版。保存不可变版本可继续沿用任务的原 pin。

只按名称分配更容易跟随目录更新，但同一助手修订可能启动不同方法版本。保存完整版本引用让改变可见；代价是停用、遮挡或来源改动后必须重新选择有效版本，不能静默切换。

## Consequences

测试覆盖过时更新、相同内容重放、导出到已有不同内容的冲突及原始包。DeepSeek 通过终端导入和导出的版本，完成原任务验证。跨设备共享仓库和线上发布另行验证。 [供应商记录](../../../../docs/experiments/2026-11-26-skill-authoring-siliconflow.json)

助手分配的合成回归覆盖主会话、返工、重启、撤回发布及配对权限。项目设置的选择、空选择、恢复默认和保存失败已用 Chromium 验证。原包副本随历史任务保存并占用磁盘，完整性检查会重读小型方法包；这不证明真实模型完成率或成本改善。
