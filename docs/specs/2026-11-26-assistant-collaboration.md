# 持久同事会话与跨助手工作交接

本机终端与 owner API 已接入持久助手协作。新任务显式选定助手修订并确认后，可派活、回交原结果和文件、返工、补充说明、答复与停止单项工作。跨设备团队及性能对照仍待验收。[使用入口](../assistant-usage.md#持久助手协作) · [能力矩阵](2026-11-25-reference-capability-matrix.md) · [固定参考源码及研究](../superpowers/plans/2026-11-26-assistant-handoff-research.md)

## 用户得到的能力

主助手在用户已授权的目标内，把独立工作交给明确版本的项目同事；同事保留自己的对话历史，可继续接收后续工作、回答补充问题和返工。用户能看到原派活、原同事会话、当前工作、文件证据和结果，停止其中一份工作后其他工作仍可推进。不同同事互相交接须保留原请求链、限制循环并遵守来源实际权限及预算。

站立会话对应OpenMausBot的“来源会话与同事之间的一条工作线程”，不等同全项目共享私人历史。新工作会话与回到已有会话分别明确；不能给临时delegate套上同事名称就称已实现持久协作。[参考调用](https://github.com/milind-soni/OpenMausBot/blob/3aec210054cd/server/drivers/agents-call.ts#L291)

## Pi 与职责边界

复用Pi 1.4.0公开的conversation、task ownership、defineDoc、configure和原生持久任务。已完成的后台锚点让同事对话跨主助手回合存在，原生deliver/report阶段负责原消息投递和原结果回传；工具调用、等待、执行、重试、恢复和计费沿Pi。自定义文档只保存同事引用、角色快照、原工作说明/归属、原文件快照和当前进度/回执，不另建运行时、调度器、队列、数据库或消息总线。[官方机制](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/packages/durable/test/examples/23-subagent-background.ts#L57)

同一原任务的模型/工具/费用/token和时限为总上限。已验证的Harness汇总包含同事会话用量；派活不补额度或执行授权。Kada暂停/取消、预算停止和目标修订需约束全部已认领/排队/运行的工作；普通Pi abort跳过后台边界的行为不是本产品默认停止策略。

多位同事复用同一registry，由各自conversation文档保存角色pin，section与执行钩子从原文档读取，不依赖registry中每个角色的可变闭包。新原生测试已证明并行读/写同事及重启后不串配置；这不代表目标来源、权限交集和业务派活验收已完成。[原生验证摘要](../experiments/2026-11-26-pi-persistent-assistants.json)

## 原工作与同事身份

- 来源：原TaskMeta、Goal修订/epoch、发起Pi conversation、工具taskId，以及原用户工作来源；工具/网页/同事输出不能成为新的授权。
- 同事：项目下Assistant的明确ID/修订、必要完整角色快照、解析后的模型及有效工具交集。来源会话、同事会话和每次工作身份分别保存。
- 工作：独立持久身份、原说明、来源/目的、固定输入文件、原投递请求、结果submission/entry和返工/待答关联。安全重放返回原回执，不重复创建会话或重派未知副作用。
- 同一站立会话只复用于相容的角色版本和有效权限范围。角色版本或权限不同应建立明确的新配置/会话，不能在旧历史上静默升级。其他来源会话和其他项目不会自动共享其私人对话。
- 目标忙时新工作使用followUp排在当前最终答复后；追加指导和原问题答复必须显式区分，不能把新工作当steer覆盖原工作。每份原工作单独列出结果，合并答复也须保留其来源关联。

## 权限、停止与循环

有效工具取来源当前实际可用范围、根目标授权及目标角色名单的交集；已有assistantPolicy负责原生可见集合、addTools过滤及逐次调用检查。目标角色的写权限不能成为只读来源绕过限制的方法。根控制工具不会自动交给同事以提交主目标；命令核验仍要求原范围允许bash。

派活提交时重检原来源仍活动、目标角色和项目、原Goal修订/epoch及预算。每份派活保存祖先链，拒绝向自己或祖先返还、重复形成等待环，保留有界深度/工作数量；达到限制说明未派发，不靠改名、新会话或换工具绕过。[OpenMausBot实际祖先/停止检查](https://github.com/milind-soni/OpenMausBot/blob/3aec210054cd/server/runtime-coordinator.ts#L258) · [Rakazo原来源与目标重检](https://github.com/elie222/rakazo/blob/e64d73292179/packages/adapters/src/bots/group-handoff.ts#L74)

停止针对显示的原工作和当前版本，保留用户停止决定；迟到点击不能停止该同事更新后的另一份工作。用户原请求未改变前不能自动重新派发已停止内容。停止/取消保留会话历史和已经写出的文件，并从原回执说明实际状态，未知外部效果不能当成已撤销。主目标不得在必要同事工作尚未结清或待用户答复时标为完成。

## 文件和回交

输入文件须来自原允许工作区，保存实际路径、大小和SHA-256，复制时核对原内容；过大、越界、链接逃逸或复制期间变化明确失败，不先声称已经传递。二进制与空文件保留原字节。固定输入进入原工作独立目录，不覆盖后来文件。

同事结果作为有来源的数据回交主会话，带工作ID、目标会话、原角色版本和实际产物引用。主助手从原文件/验收核对最终结果，不能据同事自称完成而跳过核验。回交前再次核对来源控制与Goal修订；过时或已取消工作仍可查原结果，但不能自动恢复主任务。重复报告不新增主输入或模型请求。[Rakazo原文件与去重交接](https://github.com/elie222/rakazo/blob/e64d73292179/packages/adapters/src/bots/group-handoff.ts#L99)

- [ ] 原Pi承载的具名站立同事跨多份工作、重启、压缩仍保留相容原历史；new与已有会话明确区分，不改原助手配置。
- [ ] 用户确实指定目标和版本后才派活；普通聊天保存配置不开始工作，准备阶段不能提前执行，旧/远程/子任务不自动获得新的派活权限。
- [ ] 分别验证同事独立模型/指令、父目标总预算、角色/源工具交集，嵌套、MCP加载、Skills、命令核验和多跳交接不能扩大权限；来源或目标配置变化可见。
- [ ] 两份工作排队、补充指导、待用户答复、继续、返工和读取原结果均绑定原工作；并发派活、目标忙及用户迟到操作不误投。
- [ ] 祖先链/等待环、深度/总量、重复派发和用户停止决定均有实际失败用例，未派发时零模型/工具副作用。
- [ ] 固定输入与结果传递覆盖二进制、空文件、原哈希、并发修改、越界与大小限制；结果不冒充独立核验或授权。
- [ ] 主目标暂停/取消、时限/token到限及Goal修订停止对应同事工作；迟到结果不唤醒旧目标，不续预算；其他有效工作保留原范围。
- [ ] 实际SIGKILL覆盖认领、投递后未回执、结果已决定、报告后未回执及停止窗口；恢复不重派已提交外部动作，未知结果明确保留。
- [ ] 用户从owner API/终端及原任务视图能查询同事、原工作/文件/用量、答复问题与停止原工作；真实模型通过多份工作和返工验收，再按目标平台验证UI。
- [ ] 同模型/工具/权限的原Pi基线对照完成率、人工介入、恢复和用量；功能增加与已证明收益分开。类型、聚焦/全量、笔记及提交检查后推送Fork，不创建上游PR。

## 阶段1业务核心及当时界限

`assistant-peer-state.ts`保存原工作身份、Goal修订/epoch、来源/目标、原生任务/消息/结果、角色与有效范围、文件快照、祖先链和停止决定。认领与原生分配同一Pi事务提交，失败一起回滚；相同意图返回原身份，异内容冲突。相容的standing会话可重用，new会话独立保存kind，必须显式选中才能复用为已有工作线程。

派活总量和用户停止决定绑定原根任务，不随修订/epoch或重复回执清除；深度按工作边计算，不因根角色是否具名而改变。来源同事必须保留其固定工具范围，owned会话不能冒充根。Goal的新增opt-in约束禁止未回交工作时提交，同时拒绝同事误用主任务工具读取私有要求、提交或阻塞主Goal。默认Goal不读取/创建该文档，Runtime尚未启用此选项。

结果来自对应原生submission，不等于最终产物已经独立核验；原报告未进入来源回合前仍未结清。停止为请求/确认两步，冻结后代，从叶子核对原生任务及输入确已终止后才确认；不能据“请求停止成功”宣称动作已撤销。

21项业务核心测试及严格公开类型检查通过，包含实际SQLite两次重开与原生归属保留。它们使用合成模型，不是新的真实模型端到端验收。输入快照元数据限制5项、每项5MiB；实际复制、源哈希复核、owner重新授权、完整投递回交和新报告器SIGKILL尚未实现，不勾选上述产品验收项。

与现有Pi机制、固定角色、委派、运行时、任务确认及恢复合并的55项回归通过，类型/构建和笔记/提交检查通过。此次未重跑整仓全量，不能把前一项功能的539通过套到当前工作树。新增独立复核尚未完成，已知审查通道的认证/任务投递故障没有修复；作者检查和测试不等同独立审查。[阶段1验证记录](../experiments/2026-11-26-assistant-peer-state.json)

## 内部派活与回传扩展

`src/assistant-peers.ts` 使用原 Pi 锚点和持久 deliver/report task；`assistant_assign` 以工具 taskId 和 durable memo 固定原角色、模型、来源修订、实际工具交集及工作模式。standing、新会话和明确已有会话保留独立身份，忙时沿 followUp 排队。嵌套工作从当前 `LiveDoc.run.inputs` 识别原父工作，不用可被排队覆盖的“当前工作”指针。

只读 `assistant_directory` 分页返回当前原项目的角色元数据，不返回指令；`assistant_work` 和 `assistant_result` 只读当前来源派出的工作及原生 answer entry。报告保存稳定 requestId，来源等待用户时用 Pi 持久睡眠保留结果，恢复工作后再回传。回传事务只带出复制后的投影与标量，不让已提交的 Pi draft 逃逸。

`assistant_rework` 必须引用同来源已结清的原工作，创建新的 `reworkOf` 关联并保留原会话、完整角色 pin、模型及有效工具范围；后来修改或归档目录不会替换旧 pin。原来源已失去的工具不能借返工重新取得，旧结果和说明不被覆盖。原理参照 [OpenMausBot 明确返工与去重](https://github.com/milind-soni/OpenMausBot/blob/3aec210054cd/server/runtime-coordinator.ts#L258)，原回交身份参照 [Rakazo 原投递键](https://github.com/elie222/rakazo/blob/e64d73292179/packages/adapters/src/bots/group-handoff.ts#L99)。

35 项聚焦验证包含 21 项业务核心、11 项派活集成及 3 项真实 SIGKILL。覆盖排队后的独立答案、多跳及祖先拒绝、嵌套/加载工具隔离、专属模型与压缩、原角色返工、等待用户后的报告，以及派活回执、外部动作回执和报告回执窗口的恢复。外部动作使用 Pi 非安全重放工具，强杀后保留不确定结果而不重做；合成文件计数验证只发生一次。此阶段没有真实供应商验收。

Runtime 尚未安装该扩展，不能从正常任务入口使用。固定文件复制、工作提问/指导、精确停止与预算/修订清理、owner 视图和完整恢复/真实模型验收仍须完成；不勾选整项产品验收，也不将完整协作目标标为完成。

本阶段整仓 `npm test` 为 578 通过、0 失败、4 项可选 Office 依赖跳过；另加的选择性停止原生探针单独 1/1 通过。生产类型/构建、四个相关测试文件的严格公开类型、笔记及提交检查通过。独立审查未完成：子代理两次未收到正文；CLI helper 在 Windows 读文件快照时因访问时间变化拒绝，未形成审查或凭据扫描结论。没有真实供应商运行。[派活阶段验证记录](../experiments/2026-11-26-assistant-peer-dispatch.json)

## 内部单工作停止与固定文件

内部 `stopAssistantWork` 保存用户停止后按原父链从叶子取消对应原生输入、generation 和报告任务，终止确认后才更新业务回执。其他同事和同会话排队输入保留；重试确认后的原停止能补齐 Pi 被动 final boundary，来源禁用、过期或目标轮次改变时不唤醒。四项集成、停止请求与确认后两处 SIGKILL 通过。Runtime、owner API 尚未接入，不能从模型工具伪装 owner 停止。

`assistant-files.ts` 复用 Workspace 的目录边界与原始字节检查。`assistant_assign.files` 接受至多 5 个、每个 5 MiB 的原文件，Pi memo 保存原路径、长度、哈希和独立目的路径；先完成复制才认领派活。临时文件写入并 sync 后通过同目录硬链接发布，若已有不同文件则失败，绝不覆盖后来编辑。文件仍是普通工作区文件，所谓“固定”指原哈希绑定和拒绝覆盖，不代表 OS 不可修改。

同事的 `assistant_attach` 将当前原工作产物复制到独立 outputs 路径，保存原工具请求回执和哈希，报告与结果投影附带原 outputs。返工复制原输入版本而非后来源文件，并拒绝被改动的原固定副本。文件路径和结果仍需主助手按原验收独立核查，不因摘要中有路径而视为合格交付。[固定源码实现参考](../superpowers/plans/2026-11-26-assistant-handoff-research.md)

文件回归覆盖二进制/空字节、过大/重复/越界/链接、并发重放不覆盖、复制中变更、原件后续修改及原副本被改后返工拒绝；两处额外实际 SIGKILL 验证复制完成未认领与输出副本完成未回执时，源文件改变后恢复仍保留原字节。当前83项相关组合通过，后加源私有记忆/准备区隔离回归单独通过。整仓在当前实现再次运行，结果须以最终输出为准。

本阶段当前整仓600项中596通过、0失败、4项可选Office跳过，含上述源私有prompt回归。7处实际SIGKILL均已通过；硅基流动DeepSeek V3.2以24次请求完成首次派活/文件、重启后同会话回忆及修改/归档配置后的原角色返工。第一次验收脚本错传项目子目录被正确拒绝（8次请求），失败记录保留；修正脚本使用实际assistantProject，未放宽产品边界。费用元数据未配置，money=null，不据零字段声称免费。本轮没有工作待答/指导、Runtime全生命周期、owner入口或原Pi收益对照，仍不勾选全部产品验收。[停止与文件证据](../experiments/2026-11-26-assistant-peer-files-and-stop.json) · [真实模型](../experiments/2026-11-26-assistant-peer-live.json)

## 本机协作入口与恢复

新本机任务通过 `--collaborator ID@修订` 或 owner API 固定助手名单。准备阶段保留原确认入口，确认后才向模型注册派活工具。终端可读取原工作和结果、答复、补充说明及按已显示版本停止单项工作。已选角色与工作随原任务接回。测试核对未选助手、其他任务的工作 ID、迟到答复及未认证 API 的拒绝行为。[入口回归](../../test/assistant-peer-entry.test.ts)

原任务监督器在改目标、暂停、取消、时限或 token 到限时停掉关联工作，保留原工作、原时限和已有证据。派发模型与工具前也检查原预算。真实进程强杀新增两处窗口，分别在答复及停止已持久保存后恢复。测试核对原 ID、报告数量及实际副作用。[生命周期回归](../../test/assistant-peer-lifecycle.test.ts) · [强杀回归](../../test/assistant-peer-recovery.test.ts)

DeepSeek V3.2 在硅基流动完成两份工作。终端重启后向原问题答复，返工沿同一同事会话读取原选择，固定副本、工作区文件和交付证据的 SHA-256 一致。最终 17 次请求、118,982 token，其中 102,144 为缓存读取，账单金额未知。此前三次尝试保留，其中两次到限。复现发现主助手重试提交会挡住排队的原报告，现由原提交工具结束该回合，使 Pi 能继续交付原报告。[真实验收记录](../experiments/2026-11-26-assistant-collaboration-runtime.json) · [原 Pi 回合边界](https://github.com/earendil-works/pi/blob/v1.4.0/packages/durable/README.md#tools)
