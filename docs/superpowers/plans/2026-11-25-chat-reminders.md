# 聊天内单次提醒实现计划

**目标：** 本机普通对话能按用户明确要求保存、查看和取消单次提醒，不需要输入命令或先创建 Goal。

**参考源码：** [OpenMausBot 查询当前时间与触发器](https://github.com/milind-soni/OpenMausBot/blob/3aec210054cd/server/drivers/agents-catalog.ts#L596)、[原触发器创建路径](https://github.com/milind-soni/OpenMausBot/blob/3aec210054cd/server/drivers/agents-call-triggers.ts#L453)、[Pots 以请求 ID 防重](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/gateway/timers.ts#L429)。独立实现薄工具，不复制外部服务或定时器。

**Pi 核对：** 1.4.0 原生 defineTool 的安全重放与 taskId 可固定请求身份；原 LocalRoutines 已有 notify/once、时间与日历校验、Pi 持久休眠及取消。提醒工具只组合这些能力。

**契约：**

- 新建本机普通聊天保存能力标记，只在其主会话安装提醒工具；旧任务、远程私有会话、任务准备和子 Agent 不获得此能力。
- `reminders_info` 返回当前机器时间、时区与同一项目的单次通知型提醒。项目身份复用 memoryProject；其他项目、任务型规则和循环规则不出现在这里。
- `reminder_create` 接受带明确时区的 ISO 时间和提醒文字，固定 action=notify、schedule=once、当前项目工作区。ID 由原聊天 ID 和 Pi 工具 taskId 派生，重启重放不重复提醒。现有 LocalRoutines 负责拒绝错误或过去的时间。
- `reminder_cancel` 参数固定 info 返回的 ID 与修订，仅取消可见范围内的指定提醒，原取消事务再次核对修订。取消不会删除历史，不更改其他项目或执行型规则；重放也不能取消后来编辑的新提醒。
- 对话指令说明：提醒是普通聊天行为，不调用 task_prepare；创建前先用 info 取得机器时间/时区，用户时区或意图不明确时澄清。只在工具成功后声称已保存，外部文档不能授权新提醒。
- CLI、API 及原提醒入口保留；通知继续进入原 inbox，不引入推送目标、外部消息或新增依赖。此版不新增循环任务管理或自动执行授权。

**文件：** 新增 `src/reminders.ts` 薄工具；`src/runtime.ts` 只在带能力标记的本机聊天挂载，`src/conversation.ts` 增加对应指令。`test/chat-reminders.test.ts` 验证真实 Pi 工具、通知、项目隔离及远程/历史边界，强杀夹具验证副作用完成但回执未保存的重放。Spec 和已有架构笔记同步。

**边界：** 脚本化模型验证工具与业务链，不能证明自然语言时间理解在真实模型上无误；提醒不是自动执行任务的授权。

## 验证记录

工具缺失先由失败回归证明；取消前规则变更的失败回归暴露了检查与取消之间的竞态，修复为原事务比较工具参数中的修订。8 项提醒专项通过，相关聊天与原规则共 32 项回归通过。最终完整 `npm test` 为 415 项：411 通过、0 失败、4 项 Office 样例因可选依赖缺失跳过。类型检查、构建、提交候选检查和三项笔记检查通过。

实际 SIGKILL 覆盖创建成功但工具未回执、取消成功但未回执，以及取消尚未发生时规则被编辑。分别保持一次通知、原取消结果和新修订不被取消。远程、准备及历史会话不自动取得工具；跨项目和执行规则不在范围内。

硅基流动 DeepSeek V3.2 对中文请求完成时间换算、真实 Pi 工具保存、daemon 重启后原会话取消，6 次请求、24,018 总 token，无 Goal，取消后没有通知。7B 独立尝试的 2 次请求产生无效工具参数，没有建立提醒；原始结果单独保留。实际金额未知。测试入口为 `KADA_LIVE_CASES=F11-chat-reminder` 的原 live-assistant-memory 脚本，单次最多 8 次请求。

主会话检查完整生产差异及调用路径。自动审查因缺少 TruffleHog 在模型审查前停止；独立审查任务正文不可读，未执行审查，没有独立审查通过结论。真实模型验证仅对应列出的时间与操作，不代表所有自然语言请求或模型。
