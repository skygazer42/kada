# Telegram 私聊任务入口

本机用户为一个专用 Telegram Bot 配置私聊用户 ID 和 Kada 配对设备。启动 `npm run harness -- telegram` 后，该用户可以发送文字和文档、确认任务说明、回复主任务和子任务的待答并接收核验后的产物。输入 `/new` 开新会话，回复已收到的消息可继续其原会话。任务在现有 daemon 的配对工作区中执行。

Pots 用长轮询读取事件，在推进平台偏移量前保存事件，并在发送前记录发送意图。Telegram Bot API 无法按发送意图查询历史，因此中断的发送保留为待核对状态。Kada 用原 Telegram 消息 ID 提交到已有 Pi 会话和回执接口。Telegram 配置保留环境变量名，发送记录保存会话、动作和平台消息 ID。 [Pots 入站确认](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/channels/telegram/index.ts#L173) · [Pots 出站回执](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/gateway/outbox.ts#L54)

- 接收配置用户的私聊文字、按钮和 5 MiB 以内的文档。确认绑定已显示的任务修订与摘要，答复绑定原会话和问题。文档复用手机入口的工作区、格式和 SHA-256 检查。 [Pots 文件下载](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/channels/telegram/index.ts#L692)
- 同一 Bot 在同一数据目录只运行一个轮询进程。反复投递用原 Telegram 消息 ID，收到 Kada 回执后才保存下一条平台偏移量。Kada 与桥接进程可以分别重启。
- 每次发送先保存意图。发送结果不确定时保留记录。用户可用 `/status` 重新显示当前待确认或待答内容，或用 `/delivery` 重新请求当前核验产物。目录中的文件由原核验链接读取。
- 本地 Bot API 测试服务覆盖专用私聊、重复投递、独立文档字节、原确认、主任务和子任务答复、分别重启 daemon 与连接器、原报告下载和明确补发。另覆盖过期按钮回执、长时间停机后的新 Telegram 偏移量、切换后回复旧会话及过大文档。真实 Telegram Bot 的部署独立验收。 [端到端回归](../../../test/telegram.test.ts)
