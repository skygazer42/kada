# 聊天中的 MCP 连接建议

Rakazo 从当前调用创建 MCP 连接并关联原对话的审批卡，已有连接发生名称冲突时保留原配置。Kada 的普通聊天可提出 HTTP MCP 连接，用户在原会话查阅和决定。通过后用现有 MCP 目录测试连接、选择启用的工具，并配置当前项目范围。[工具入口](https://github.com/elie222/rakazo/blob/e64d73292179/packages/adapters/src/tools/builtin-conversation.tool-definition.ts#L234) · [持久注册与审批](https://github.com/elie222/rakazo/blob/e64d73292179/packages/adapters/src/mcp/mcp-server-tool.ts#L129) · [原工具设置](../../../src/mcp-tools.ts)

- 建议固定原本机对话、项目、Pi 工具 ID、连接名称与 HTTP 地址。地址校验沿已有 MCP 配置规则，配置文本沿已有凭据脱敏规则检查。提议与查看建议以原项目为范围。
- 用户允许后，原配置事务登记一个待测试的停用连接，同时保存应用回执。拒绝、冲突和重放保留原连接。既有命令用来实际测试、启用指定工具、配置项目选项或登录 OAuth。
- 测试覆盖旧数组配置、原对话重启、同名冲突、批准、拒绝和重复批准。验收记录提议与登记时的网络调用次数，以及后续测试和工具启用的真实步骤。

用户也可从对话提出设定项目工具名单。建议列出当前选择及候选工具，固定被涉及连接的当前修订与可用范围。批准沿现有项目工具规则保存设置，回执与设置写入同一个事务。已有运行保留其 Pi 工具范围。[Rakazo 分配确认](https://github.com/elie222/rakazo/blob/e64d73292179/apps/api/src/routes/mcp.ts#L621) · [项目工具快照](../../../src/mcp-tools.ts)

## 验证

本机回归通过原服务端、真实 HTTP MCP 测试和工具调用核对以下路径。连接建议登记后处于待测试状态，重复批准保留原回执。项目工具建议支持指定工具、空名单和恢复全局继承。选择与当前配置不符时返回冲突。回归还覆盖旧配置、另一个项目、后来的手工修改与真实 SIGKILL。[测试](../../../test/mcp-proposals.test.ts)

两个硅基流动场景各用了 4 次模型请求。第一个场景登记并探测本地合成 MCP，只启用状态工具，新任务实际调用一次。第二个场景将项目工具范围设为空，原任务和另一项目保留各自的工具，新任务的范围为空，改范围没有触发连接。[实测](../../experiments/2026-11-26-mcp-proposals-deepseek.json)

全量 638 项通过，最终相关回归 64 项通过。编译后的 CLI 完成连接登记、实际测试、选择工具及项目范围变更，原 Pi 工具快照仍可查阅。
