# Discord 私信任务入口

本机用户为专用 Discord Bot 配置一个用户 ID 和一个 Kada 配对设备。启动 Kada 的 Discord 连接器后，该用户可在 Bot 私信中提交文字和文档，按原消息回复以确认任务或答复待问，并接收核验产物。任务保留在原 daemon 的配对工作区。Discord 和 Telegram 共用 Kada 已有的任务接口和收发记录逻辑。

Pots 在启动及断线后按 Discord 消息 ID 补读，用发送 ID 派生 nonce。Kada 针对单个已授权 Bot 私信读取历史，保留最后处理的消息 ID，按平台消息 ID 提交到现有 Pi 会话。发送使用稳定 nonce，发送回执丢失时保留本机记录。 [Pots 私信选择](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/channels/discord/index.ts#L1026) · [Pots 历史补读](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/channels/discord/index.ts#L950) · [Pots 发信 nonce](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/channels/discord/index.ts#L997) · [Discord 消息 API](https://docs.discord.com/developers/resources/message)

- 首次连接记录当时最新的消息 ID。后续重启从原位置分页补读，旧消息按升序受理。只接受配置用户在该 Bot 一对一私信发送的内容。
- 回复 Bot 的原任务说明并发送 `!confirm`，确认绑定已显示的修订和摘要。回复原待答时复用主任务或子任务的原问题 ID。`!new` 打开独立会话，`!status` 可重新显示当前待处理内容，`!delivery` 可明确请求核验产物。
- 文件从 Discord 提供的 CDN 链接读取，按现有配对接口校验并保存原字节。连接器只访问该私信；自动回复关闭 Discord 提及解析。
- 测试使用本地 Discord API 和真实本机 Kada daemon。验收覆盖首次连接、重启后补读两页历史、私信和文档归属校验、原确认、daemon 重启后答复和输入及产物字节。模拟明确限流时用原 nonce 重试。另在文件送达、回执仍未返回时强制终止 CLI 进程，重启后保留原记录，通过用户命令补发。Telegram 旧版生成的任务说明和回执也通过新版接回和交付。真实 Discord Bot 待实测。 [Discord 回归](../../../test/discord.test.ts) · [Telegram 回归](../../../test/telegram.test.ts)
