# Kada Fork 个人助手开发计划

2026-11-23。代码基线为 Fork 的 `092cc43`。本文列出下一阶段的产品功能、实现顺序和验收场景，待开发项目使用复选框记录进展。

逐功能的源码文件、关键符号、接口与测试条件见 [个人助手功能 Spec](../../specs/2026-11-23-personal-assistant.md)。

## 开发目标与协作方式

把 Kada 做成能理解项目背景、接下目标、持续推进、主动提醒并交付结果的本地个人助手。首期用户入口是终端，macOS 客户端消费同一套本地 API。个人助手的产品能力在 TypeScript、Node.js 和 Pi 的现有结构上逐项补齐。 [当前产品范围](../../../SPEC.md) · [项目约束](../../../AGENTS.md)

开发和推送使用 `skygazer42/kada` 的功能分支，`origin` 指向 Fork，`upstream` 用于跟踪 `muzizhi7/kada`。当前阶段先在 Fork 迭代，上游 PR 由用户后续安排。此前创建的上游草稿 PR #1 已关闭。

第一批功能定为 **工作记忆管理、任务交接工作台、模型设置**。之后推进工具连接、例行任务、远程入口，最后扩展电脑操作和多助手协作。这个顺序是本次建议，远程渠道和电脑驱动仍待在对应阶段选择。

## 功能开发顺序

| 阶段 | 用户得到什么 | 主要参照 | 阶段交付 |

### P1 · 工作记忆管理

场景为用户说“这个项目以后用中文写日报”，下次在同一项目继续做事时直接采用，并能看到这条背景的来源。用户随后说“改成英文”或“忘掉这条”，后续任务体现这次修改。

- [x] 给现有记忆视图增加当前项目筛选、来源、时效和适用范围。
- [x] 增加用户直接纠正和遗忘的入口。纠正生成可追溯的新事实，遗忘停止该事实的检索与注入；再次扫描原始来源时保留遗忘决定。
- [x] 把当前任务实际采用的记忆 ID 和版本关联到任务。任务状态能解释采用了什么，用户可以回查。
- [x] 复用现有独占写入与原子保存，在并发修改时提示冲突。旧任务继续读取其保存的上下文。

主要修改 `src/user-memory.ts`、`src/discovery.ts`、`src/runtime.ts`、`src/server.ts`、`src/chat.ts` 和对应测试。任务视图承接记忆引用摘要。

验收包含两个项目的冲突偏好、改正后重启、遗忘后重扫，以及扫描到旧来源时的行为。检查当前对话无需额外自我介绍，旧事实有解释，新任务使用当前有效版本。遗忘操作展示其范围，原始来源文件与历史任务记录由各自的数据管理入口处理。

第一批建议按三个开发单元推进，均可单独演示。

1. 项目记忆列表与来源查看。
2. 纠正、遗忘与重扫后的持续生效。
3. 当前任务的记忆使用记录与原因展示。

### P2 · 任务交接工作台

场景为同时做资料包和代码修改，用户离开后再回来，先看到需要自己回答的问题，再看到仍在运行的工作和已生成的文件。

- [x] 在现有 `/tasks` 和任务 API 上增加运行、待处理、已交付筛选，优先呈现待用户处理的项目。
- [x] 每项提供目标、当前步骤、预算、等待原因和交付文件。使用 `/attach` 进入原任务。
- [x] 对完成、失败、预算到限和等待用户形成一次可见通知，接回后能标为已读。
- [x] macOS 客户端复用同一任务视图，提供文件和目录打开、状态和待办入口。Swift 语法及共用 API 已检查，原生界面待 macOS 验收。

主要修改 `src/runtime.ts` 的列表投影、`src/task-view.ts`、`src/chat.ts` 与现有桌面客户端。通知身份绑定任务及其事件，避免重复轮询产生重复通知。

验收为两项并行任务中一项等待用户，另一项交付。关闭客户端、重启后台和重新接回后，列表状态、问题、费用和产物可追溯，通知没有重复。完成判断继续引用实际验收。

### P3 · 模型设置、工具与方法连接

场景为首次启动选择现有供应商和模型，检查可用后开始工作。需要处理文件时，助手能找到用户已有的方法；用户清楚哪些连接已启用。

- [x] 用 Pi 当前模型目录建立设置入口，展示配置来源、连接结果和失败原因。
- [x] 核对当前 Pi 公开认证 API 支持的方式，再接账号或 API Key。已有凭据使用原有存放位置。
- [x] 将现有 Skills 发现和读取结果做成可选择的目录，显示方法来源与版本。
- [x] 对通用 MCP 连接先核对 Pi 公开扩展点，再接一个现成服务。连接启用、工具清单和权限范围可见。
- [x] 新任务采用当前模型和方法选择，历史任务按其保存的配置恢复。

落点为 `src/config.ts`、`src/models.ts`、`src/cli.ts`、`src/discovery.ts`、`src/skills.ts` 与现有本地服务。Pi 负责模型调用、认证、工具协议和会话执行。

验收为首次配置成功、错误模型、失效认证、连接暂时离线及切换后恢复旧任务。工具连接后执行一项文件任务，核对实际用到的方法和费用。

### P4 · 提醒与例行任务

首个场景为“周五 17 点汇总这个项目本周变更，只有新内容时提醒我”。

- [x] 先交付单次提醒，支持查看、修改和取消。
- [x] 再交付每日/每周任务，记录时区、执行范围、发生项标识和已经确认的预算政策。
- [x] 先用 Pi 1.4.0 的持久任务等待、`sleepUntil` 和 `onWake` 验证与现有 daemon 的接法。时间等待和任务恢复复用 Pi。
- [x] 每次触发沿用明确的任务说明和预算政策。到期时建立或接回现有任务，通知回到同一交接入口。
- [ ] 纯检查可先使用固定脚本，发现变化后再唤醒模型。对中断时可能已经产生效果的动作先核对真实结果。
- [x] 把关机错过的执行显示为错过、待确认补跑或按用户既定政策处理。

正式实现前需验证恢复睡眠任务时的归属与启动点，方案比较使用 Pi 的公开接口和现成系统触发器。自定义状态只保存例行任务定义和发生项进度。

验收覆盖关机重启、同一触发重复投递、修改/取消、时区变化和预算耗尽。每个发生项的消息、产物和费用能回查，模型费用包含检查、重试和失败尝试。

### P5 · 手机派活与远程接回

首版推荐只接一个渠道，用它跑通“手机交代整理资料 → 本机完成 → 手机收到文件或待答问题”。渠道选择在本阶段开始时确定，可从 Telegram 或轻量 Web 入口中选一项。

- [x] 远程用户、消息和附件映射到现有任务及工作区，保存稳定请求 ID。
- [x] 回传受理状态、进度、待答问题、交付文件和错误。
- [x] 重连后先查询原请求，状态不明时显示需要核对的情况。
- [x] 明确当前电脑在线状态及待处理消息。本机持有执行和恢复状态。
- [x] 远程可补充信息并回复已有确认请求，授权范围和预算沿用原任务。

采用入口薄适配，底层调用当前任务 API。验证一个渠道中的断网、重复发送、离线后恢复、附件丢失和错误账号访问。事件游标的引入依据实际丢失或重连问题，复用现有 Pi 事件与状态。

### P6 · 应用操作与按需协作

本阶段承接现有终端验证和电脑驱动选择。首个场景选一个确实需要操作界面的本地工作，例如从文件生成资料后，把内容填到应用并交用户检查。

- [x] 与用户选择现成驱动和一个真实应用流程，沿用现有 MCP 电脑桥与租约。首个验收场景为 agent-browser 本地网页。
- [x] 提供当前操作的观察入口、用户接管和回交。恢复后重新观察页面或应用状态。
- [x] 在同一个任务中连接文件、终端和应用结果，交付引用实际检查。
- [x] 独立的资料整理和代码核对可交给现有 Pi 子会话。任务视图显示职责、进度、费用和产物，主任务回收结果。
- [ ] 多个具名助手在真实角色长期分工时再扩展，明确每个角色的记忆和任务归属。

验收为一次终端与应用混合任务中的接管、回交和强制中断，再核对最终文件或应用记录。协作验证记录独立子任务是否完成、结果是否回到原目标、总费用和人工介入。

### P7 · 复用工作方法

当前已有 Skills 捕获与回退，下一步先让用户选择和复用已验证的方法。首个场景为同类资料包在不同输入上再次执行。

- [x] 把方法显示为有来源、有适用条件和版本的条目，支持停用和回退。
- [x] 在任务记录中显示实际读取、实际执行和结果。方法是否减少重复探索仍需重复对照。
- [x] 自动提炼沿用原任务预算，结合新的输入和原始验收检查验证。
- [ ] 记录成功、失败、提炼、压缩及返工的完整费用，达到现有质量与成本门槛后再扩大自动使用。

本阶段参考现有学习实验和 `src/skills.ts`。此前实验没有证明自动学习能降低合格交付成本，自动使用仍是待验证的能力。 [学习与成本](../../learning-and-cost.md)

## 本轮建议

F01—F18 已实现首期入口。agent-browser 的真实模型接管和回交，以及真实驱动传输中断后恢复，均有独立产物证据。记忆与交接的合成任务复测中，原生 Pi 完整交付，Kada 写出正确产物后达到 token 上限。真实用户任务对照和有效小时级执行待验收。 [验证记录](../../experiments/2026-11-23-assistant-validation.md)

首个远程渠道为轻量 Web，能力限定在工作区文件。真实浏览器验收范围是本地测试网页，日常配置按需启用。
