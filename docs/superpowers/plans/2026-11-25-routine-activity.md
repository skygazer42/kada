# 例行任务活动门槛实现计划

**目标：** 用户可让已开启的项目循环任务只在近期使用过 Kada、且距上次任务受理足够久时自动检查，减少无人使用期间的模型唤醒。

**参考：** [Amuse 心跳的近期活动与运行间隔](https://github.com/replit/amuse/blob/a71da98873f0/apps/server/src/agent/scheduler.ts#L97)、[Rakazo 主动检查先做免费判断](https://github.com/elie222/rakazo/blob/e64d73292179/packages/adapters/src/routines/strategic-initiative.ts#L175)。Pi 1.4.0 的原持久规则、事务和休眠负责调度与恢复。

**契约：**

- 原任务规则增加 `activity: { withinMinutes, minIntervalMinutes }`，两个正整数均最多 43,200 分钟。只允许指定工作区的循环 `task`，不用于单次、纯事件、通知或同时配置事件的规则，默认关闭。
- 活动范围是现有 memoryProject 的本机项目身份。直接用户创建任务、确认和原会话的用户追加消息算活动；自动规则首次输入、监督、委派回传、压缩和远程私有工作区不算。原 Pi 提交和事件是来源，不扫描操作系统或其他应用。
- 活动检查不请求模型，在命令/MCP 预检前执行。没有活动、活动已过期、仍在运行间隔或读取失败，都不执行预检、不受理模型任务，发生项保留原因。
- 自动受理时固定活动判断，原发生项重启恢复沿用该判断。成功受理任务才推进运行间隔；失败受理不推进。重复操作和 daemon 重启不能补预算或重复启动。
- 活动规则沿用 `overlapPolicy: skip`；上次未完成的任务优先阻止重叠。手动运行体现用户直接要求，跳过活动门槛，但仍使用原预算、预检与重叠限制，并更新后续自动运行间隔。
- 调整规则和暂停/恢复保留上次受理时间，避免编辑后绕过间隔。读取活动失败明确记为失败，不静默当作允许。

**修改范围：** `src/routines.ts` 的定义、持久受理和发生项；`src/runtime.ts` 的项目用户活动投影；`test/routine-activity.test.ts` 及现有相关测试；CLI 提示、Spec 和已有架构笔记。不增加定时器、数据库、活动采集器或依赖。

**边界：** 这是 Kada 内的用户活动条件，不代表人在电脑前，不读取全局键鼠、外部聊天或应用历史。实际任务质量与成本收益仍需真实用户任务比较。

## 验证记录

最终完整 `npm test` 共 394 项：390 通过、0 失败、4 项可选 Office 样例跳过。类型检查、构建、CLI 帮助、提交候选凭据检查及三项笔记检查通过。聊天转为 Goal 时活动时间丢失先经失败回归复现，最小修复后转换/重启及既有活动语义相关 16 项通过，再完成此全量检查。

实际 SIGKILL 验证受理后、回执前中断仍保留原任务、allowed 判断与创建时间；恢复不重复模型调用，后续发生项遵守原间隔。本地 API 验证未授权请求拒绝，无活动时零模型请求，用户活动后受理一次，daemon 重启保持间隔。

自动审查执行 `autoreview --mode local`，因缺少 TruffleHog 在模型审查前停止；独立只读审查任务和补充范围均不可读，未执行审查。本轮没有独立审查通过结论，主会话已检查完整生产差异及相关调用。
