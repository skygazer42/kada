# Microsoft Teams 私聊任务入口

Kada 用微软 Teams SDK 的 Socket Mode 接入一个已安装的专用应用。配置绑定一个组织、一个用户及一个 Kada 配对设备。用户在一对一私聊发文字或文档，在任务卡确认或答复原待问。产物经本人接受文件邀请后上传到 Teams 提供的位置。

Pots 用微软 SDK 接收已验证的活动，先保存活动再返回回执。Kada 沿用这个顺序，把原活动交给现有配对任务流程。任务卡操作绑定原显示记录，文件上传按原核验版本读取。 [Pots SDK 接入](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/channels/teams/sdk.ts#L6) · [Pots 活动回执](https://github.com/Crokily/pi-durable-bot/blob/38486add7c1f/src/channels/teams/index.ts#L445) · [微软文件同意流程](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/how-to/bots-filesv4)

- 接收范围固定为配置组织、用户和该 Bot 的一对一会话。原文字、卡片操作和文件同意活动都按原 ID 去重。通过配对接口保留原任务、主问题及子问题归属。
- 文件接收复用 Kada 现有字节和大小核验。发送时记录文件邀请与原产物版本，收到同意后再上传。回复 `!status` 可恢复待确认及待答内容，`!delivery` 可重新请求文件。
- 本地 Microsoft Bot API 模拟使用真实 Teams SDK 的 Socket Mode 活动分发。回归覆盖入站保存、卡片确认、重启接回答复和文件邀请。拒绝过的邀请即使随后收到接受也保持关闭。接受时若产物已改动，连接器会报告原文件不可用。恢复原字节后可重新请求邀请并验证上传内容。真实组织 Socket Mode 和平台离线私聊补读待后续验收。 [端到端回归](../../../test/teams.test.ts)
