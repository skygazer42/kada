# MCP OAuth Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** 让本机用户给 HTTP MCP 连接完成 OAuth 登录、恢复使用和本机退出，账号授权由现有 MCP 服务承担。

**Architecture:** 复用已安装 MCP SDK 的 OAuth、PKCE、令牌交换和刷新。Kada 增加薄 `OAuthClientProvider`、受限本机凭据文件和 owner API；连接权限、任务与执行继续使用原 `McpTools` 和 Pi。

**Tech Stack:** TypeScript、Node.js、MCP SDK 1.32.2、现有 SerialQueue 与 atomicJson，无新依赖。

**Spec:** [能力对照](../../specs/2026-11-24-assistant-capability-parity.md)中“应用连接器与主动检查”的账户连接缺口。

## Global Constraints

- Fork 为 `skygazer42/kada`，功能分支 `codex/assistant-plan`，不创建上游 PR。
- 保留现有环境变量凭据和用户配置，OAuth 仅在 HTTP 定义显式设置 `oauth: true` 时使用。
- 使用 SDK 的协议逻辑，不重建 OAuth 服务、Agent 运行时或数据库。
- HTTP OAuth 仅允许 HTTPS；合成本地验收允许 loopback HTTP。
- 登录完成后需重新测试并启用工具；后台调用不自动发起浏览器授权。

## Review Focus

- state、端点、凭据代次与登录尝试绑定；错误回调不能交换令牌。
- 退出或修改端点后，迟到回调和刷新不能恢复旧凭据。
- 重启可继续有效登录并使用原授权；授权码结果未知时不自动重放。
- OAuth 同一连接的网络操作串行，避免并发刷新令牌轮换冲突；取消仍走原操作信号。
- 刷新后的 access token、refresh token 和 client secret 不出现在公开状态或 MCP 工具结果。

**Interfaces:** `McpTools.login(id, redirectUrl)` 返回授权 URL 和期限；`finishLogin(state, code)` 完成原尝试；`logout(id)` 清除本机凭据并停用原工具。`GET /v1/settings/mcp/oauth/callback` 只凭有效一次性 state 接受浏览器回调，其他管理入口仍需 owner 凭据。
